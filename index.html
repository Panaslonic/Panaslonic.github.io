Lead Enrichment PipelineAlbato (iPaaS), 2025–2026 · consulting contract

A FastAPI backend that takes a list of company domains and turns each into a qualified, personalised outreach target for the SDR team. Excel in, enriched Excel out, HubSpot deals in sync.

site check→geo / language→firmographics→SaaS & vertical (LLM)→tech-stack match, 5,000+ apps→decision-maker & email→outreach rules→pitch + first-integration proposal

A JSON-driven orchestrator runs a different chain per buyer persona (sales, CTO, CPO, founder, partnerships, customer success) with conditional branching, batching and resume. The same steps are exposed as tools to an LLM agent with a chat UI; dedicated agents handle pipeline scoring and follow-ups.

What I did: everything — architecture, ~20k lines of async Python, data model, 26 endpoints, auth and monitoring, deployment behind the company LLM gateway.

  • Python / FastAPI
  • PostgreSQL
  • Gemini, DeepSeek, Claude via OpenRouter
  • FullEnrich, Amplemarket
  • HubSpot API
  • Docker

SecondBrainOwn product, 2026– · private repo, demo on request

A memory bank that ingests Telegram and Yandex Messenger chats, forwarded email, Granola meeting transcripts, Linear issues and GitHub activity, and agents that reason over it. With the full context of every task, they do more than answer “what did X promise and when”: they surface unanswered commitments and silent projects, compare promised with done, draft the follow-ups and close routine tasks themselves. The brief above is its daily output.

What I did: all of it, on my own time. Now being adopted by the agency group under an inner-source agreement; a Claude-based GTM agent team is being assembled to take it to SMBs.

  • Hindsight
  • Claude, MCP servers
  • Python
  • Telegram
  • Linear API, GitHub API

How I work

Small, pragmatic architectures. I pick MCP, APIs and open-source frameworks over custom code wherever they fit, and I know from running them where a custom piece is worth it.

Prototype fast, throw away what does not work. Everything above started as something embarrassing that one real user tried the next day.

Decide before requirements settle. I am comfortable making the architectural call early and changing it when the evidence says so.

GTM is my domain, not a client vertical. Fifteen years building products whose success was measured in a sales funnel, so I know which signals sales teams trust and why most “AI for sales” tools are ignored after two weeks.
